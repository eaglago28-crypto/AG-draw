Compiler, lancer, tester

AG Draw se compile depuis les sources — il n'y a pas encore de version préconstruite à télécharger. Voici comment obtenir un binaire qui tourne.

Prérequis

  • CMake ≥ 3.21
  • Un compilateur C++20 (GCC, Clang ou MSVC)
  • Qt 6 — module Widgets, plus Test pour exécuter les tests

Sur Debian/Ubuntu :

sudo apt install qt6-base-dev qt6-base-dev-tools

Configurer et compiler

cmake -S . -B build
cmake --build build -j"$(nproc)"

Lancer l'application

./build/apps/agdraw/agdraw

Exécuter les tests

cd build
ctest --output-on-failure

Sur une machine sans affichage (CI, conteneur headless), les tests d'interface utilisent automatiquement QT_QPA_PLATFORM=offscreen, déjà configuré dans tests/ui/CMakeLists.txt.

Structure du dépôt

Trois modules sont compilés aujourd'hui : l'interface (ui), le moteur de dessin (engine) et la gestion des fichiers (io). Le moteur héberge pour l'instant les outils, les calques, les effets et les deux chantiers IA (texte → vecteur, croquis → vecteur) sous une même bibliothèque.

RépertoireContenu
src/uiFenêtre principale, barre d'outils, panneaux (calques, pages, macros), barre des propriétés
src/engineScène du document, formes, outils, effets, historique annuler/rétablir, reconnaissance de formes, texte → courbes
src/ioFormat natif .agd (JSON), export PNG, export PDF vectoriel, séparations CMJN
Réservés, pas encore peuplés : src/ai, src/effects, src/text, src/images, src/layers, src/cloud et src/plugins existent comme emplacements prévus par docs/ARCHITECTURE.md pour une future séparation en bibliothèques indépendantes. Les fonctionnalités correspondantes tournent déjà, mais vivent aujourd'hui dans engine et ui.

Format de fichier

Le format natif .agd est du JSON lisible : pages, calques, formes et leurs effets y sont sérialisés directement, sans format binaire propriétaire caché.
